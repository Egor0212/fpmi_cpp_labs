# Расчетно-графическая работа №3. STL. Адаптеры над контейнерами

Требуется реализовать архитектуру системы управления аэропортами. Ваша задача — реализовать класс `Dispatcher` (диспетчер), который выступает центральным координатором и управляет перемещением данных в пределах аэропорта.


## Постановка задачи

Аэропорт разделен на зоны, каждая из которых использует свой контейнер / адаптер STL:

1. **Склад багажа вылета**: зона, куда свозится багаж для погрузки в самолёт.
2. **Зона ожидания вылета**: самолеты, готовые к взлету (в порядке очереди).
3. **Зона ожидания посадки**: самолеты, ожидающие посадки. 
4. **Перрон прибытия**: самолеты, которые уже приземлились и ожидают выгрузки (в порядке очереди).
5. **Зона выгрузки контейнеров**: зона, куда физически паллеты выгружаются из самолета.
6. **Багажная карусель**: лента, с которой пассажиры забирают свой багаж (в порядке очереди).


## Технические требования

### Сущности и их свойства

1. Багаж (`Luggage`): **уникальный** идентификатор (`luggage_id`), вес (`weight`).
2. Паллета с багажом (`LuggagePallet`): идентификатор рейса (`flight_id`), список пассажирского багажа.
3. Рейс (`Flight`): 
    - **уникальный** идентификатор (`flight_id`),
    - остаток топлива (в $\%$),
    - статус (вылет: `DEPARTUE`/ прибытие: `ARRIVAL`),
    - приоритет при посадке (сигнал бедствия: `SOS` / без приоритета: `NO_PRIORIY`),
    - список паллет на борту.
4. Действие диспетчера (`DispatcherAction`): тип действия, идентификатор рейса (`flight_id`), время.

### Зоны аэропорта

Ниже приведу некоторые замечания, касающиеся работы зон аэропорта.

**Склад багажа вылета**. Паллеты прибывают на склад в разное время. Когда самолет готов к загрузке, диспетчер должен найти на складе все паллеты для этого конкретного рейса и изъять их, не нарушая порядок остальных.

> Самолёт считается **загруженным**, если в нём есть хотя бы одна паллета с багажом.

**Зона ожидания посадки**. Самолеты кружат над аэропортом. Диспетчер должен вызывать на посадку не по порядку прибытия, а по приоритету:
- Самолёты, подавшие сигнал бедствия (SOS), приземляются вне очереди.
- Среди остальных самолётов сначала приземляются те, у кого _критически мало топлива_ ($< 10\%$).

**Зона выгрузки контейнеров**. Контейнеры вываливаются в тупик стопкой. Достать можно только верхний.

### Обязанности диспетчера

Каждое действие диспетчера (выдал команду на посадку, отправил багаж и т.п) сохраняется в **журнал диспетчера**, который сохраняется в файл `actions.txt` при завершении работы программы.

Класс `Dispatcher` должен предоставлять следующий интерфейс для работы:

- **Загрузка багажа** (`LoadLuggage()`). Найти на складе все паллеты, принадлежащие первому в очереди самолету на вылет, погрузить их на борт и корректно удалить со склада. Если паллет на складе пока нет, самолет ожидает.
- **Разрешение на взлёт** (`AllowTakeoff()`). Разрешить взлет первому самолету в очереди в зоне ожидания вылета (предварительно проверив, что он загружен), удалив его из системы.
- **Разрешение на посадку** (`AllowLanding()`). Разрешить посадку самолёту из зоны ожидания, учитывая его приоритеты при посадке (статус SOS, критически низкий остаток топлива или просто первому самолёту без приоритета), и переместить его на перрон прибытия.
- **Разгрузка самолёт** (`UnloadPlane()`). Переместить все паллеты с первого самолета на перроне прибытия в зону выгрузки, сформировав из них стопку, и освободить перрон для следующего рейса.
- **Распаковка багажа на карусель** (`UnpackPallet()`). Взять верхнюю паллету из стопки в зоне выгрузки, распаковать её и выложить всё содержимое на багажную карусель. Далее пассажиры забирают свой багаж (в порядке очереди).

## Симуляция работы системы

После того как вы реализовали описанные выше сущности, нужно проверить работоспособность вашей системы. Так как с тестированием вы уже познакомились при выполнении предыдущих работ, предлагаю вам реализовать проверку вашей системы через _имитационное (дискретно-событийное) моделирование_.

### Общие требования

Симуляция должна быть реализована в виде дискретной модели времени с пошаговым выполнением (тики). Каждый тик $t = 0, 1, 2, \ldots, T - 1$ ($T$ — максимальное количество тиков) происходит следующее:
1. Генерация случайных событий.
2. Автоматический вызов действий диспетчера.
3. Визуализация текущего состояния системы (например, вывод на экран).

> Обращаю внимание на такую характеристику модели, как её **детерминированность**: При фиксированном значении `seed` генератора случайных чисел симуляция должна давать идентичные результаты при повторных запусках (про генерацию можно почитать [здесь](../../tutorials/random_tutorial.pdf)).

### Генерация событий

В каждом тике с заданной вероятностью $P$ генерируются следующие события:

1. Прибытие паллеты с багажом ($P = 40\%$):
    - Идентификатор рейса (`flight_id`) берётся случайный из уже существующих рейсов (если рейсов нет — генерация прекращается).
    - Генерируется 5-10 экземпляров багажа (`Luggage`) весом (`weight`) от 5 до 20 килограмм, каждый со своим уникальным идентификатором (`luggage_id`).

2. Появление самолёта ($P = 25\%$):
    - Генерируется новый уникальный идентификатор рейса (`flight_id`).
    - Статус (`DEPARTUE`/ `ARRIVAL`) генерируется с вероятностью 50%.
    - Для самолётов со статусом `DEPARTUE`:
      - список паллет с багажом не генерируется (остаётся пустым);
      - уровень топлива составляет $100\%$;
      - нет приоритета при посадке (`NO_PRIORITY`).
    - Для самолётов со статусом `ARRIVAL`;
      - сгенерировать 2-5 паллет с багажом (ID паллеты = ID рейса), по 2-5 экземпляров багажа в каждой;
      - уровень топлива генерируется от $5$ до $50\%$;
      - с шансом $15\%$ на борту самолёта сигнал бедствия (`SOS`), иначе `NO_PRIORITY`.

3. Событие не генерируется ($P = 35\%$).

### Действия диспетчера

Выполняется после генерации событий. Диспетчер делает **не более одного действия за тик**:
1. В первую очередь нужно посадить самолёты с сигналом бедствия (`SOS`) на борту. Если таковых нет — посадить самолёты с низким уровнем топлива. Если таковых нет — перейти к пункту 2.
2. Если в зоне ожидания вылета есть самолёт, попытаться загрузить его и дать разрешение на вылет (если самолёт удалось загрузить). Если таковых нет — перейти к пункту 3.
3. Если в зоне ожидания посадки есть самолёт — выдать ему разрешение на посадку. Если таковых нет — перейти к пункту 4.
4. Если на перроне прибытия есть самолёт — разгрузить его содержимое в зону выгрузки контейнеров. Если таковых нет — перейти к пункту 5.
5. Если в зоне выгрузки контейнеров есть паллеты с багажом — разгрузить из на багажную карусель.
